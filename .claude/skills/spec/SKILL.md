# 스펙 인터뷰

만들 기능:

$ARGUMENTS

위 내용이 비어 있으면 무엇을 만들려는지 먼저 사용자에게 물어본다.

## 인터뷰

AskUserQuestion 툴로 사용자를 인터뷰해서 이번 버전에서 만들어야 할 기능을 구체화한다.

- 각 기능이 어떻게 동작하는지와 엣지 케이스에 대해 묻는다.
- 뻔한 질문은 하지 말고, 사용자가 미처 생각하지 못했을 부분을 파고든다.
- 현재 코드와 `CLAUDE.md`에서 이미 정해진 사항은 다시 묻지 않는다.

## SPEC.md 작성

다 다뤘으면 프로젝트 루트에 `SPEC.md`를 작성한다. 이미 있으면 덮어쓰기 전에 사용자에게 확인한다.

- 섹션은 `목표`, `이번에 만드는 기능`, `안 하는 것`, `완료 조건` 네 개다.
- 형식은 [example-SPEC.md](example-SPEC.md)를 따른다. 예시는 형식 참고용이므로 내용은 가져오지 않는다.

### 목표

- 이 기능이 왜 필요한지 사용자 입장에서 한두 줄로 쓴다.

### 안 하는 것

- 이번에 제외하기로 한 기능이나 범위를 혼동하기 쉬운 관련 기능만 적는다.

### 완료 조건

- 완료 조건마다 AC-1, AC-2처럼 번호를 붙인다.
- 완료 조건을 충족했는지 객관적으로 판단할 수 있도록 쓴다. 어떤 상황에서 무엇을 하면 어떤 결과가 나와야 하는지 쓴다.
- 무엇이 되어야 하는지만 쓰고, 어떻게 구현하거나 테스트할지는 쓰지 않는다.
- 주요 흐름, 상태 변경, 잘못된 입력과 오류, 데이터 유지 등 이 기능에서 중요한 경우는 빠뜨리지 않는다. 대신 겹치거나 지나치게 세세한 조건은 쓰지 않는다.
- 린트나 테스트 통과처럼 매번 하는 확인은 넣지 않는다.
